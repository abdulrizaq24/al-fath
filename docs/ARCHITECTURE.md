# Technical Architecture Document
## Flutter Desktop — Pharmacy Management System

---

## 1. Tech Stack

| Layer | Technology | Alasan |
|-------|-----------|--------|
| Framework | **Flutter 3.x** (Desktop - Windows) | Single codebase, compile ke native `.exe` |
| Language | **Dart 3.x** | Null-safety, strong typing, async/await |
| Database | **Drift 2.x** (SQLite) | Type-safe SQL, reactive streams, built-in migration, relational queries |
| SQLite Engine | **sqlite3_flutter_libs** | Bundled SQLite binary, no external dependency |
| State Management | **Riverpod 2.x** + riverpod_generator | Compile-safe, testable, auto-dispose |
| Routing | **GoRouter** | Declarative, deep-linking, redirect guards |
| UI Framework | **Material Design 3** | Flutter native, theming, adaptive components |
| Charts | **fl_chart** | Line, Pie, Bar charts — ringan |
| PDF Generation | **pdf** + **printing** | Generate & preview PDF langsung dari Dart |
| Excel Export | **excel** (Dart package) | Create .xlsx tanpa dependency native |
| Password Hashing | **bcrypt** | Sama dengan stack sebelumnya |
| Window Management | **window_manager** | Custom title bar, minimum size, maximize behavior |
| Fonts | **google_fonts** | Geist / Inter / Roboto |
| Localization | **flutter_localizations** + ARB | Official Flutter i18n |
| Date/Number Format | **intl** | Locale-aware formatting |

## 3. Database Schema (Drift Tables)

Mapping 1:1 dari Prisma schema yang ada, dengan penyesuaian tipe data SQLite:

| Prisma Type | Drift/SQLite Type |
|-------------|-------------------|
| `String @id @default(uuid())` | `TextColumn` + UUID generated in Dart |
| `DateTime` | `DateTimeColumn` (stored as ISO8601 text) |
| `Decimal @db.Decimal(12,2)` | `RealColumn` (double) — atau `IntColumn` (store as cents) untuk presisi |
| `Boolean @default(true)` | `BoolColumn` with `withDefault(const Constant(true))` |
| `Json?` | `TextColumn` (store as JSON string, serialize/deserialize in Dart) |
| `Enum` | `IntColumn` mapped to Dart enum via Drift converter |
| Relation (FK) | `TextColumn` + `references(OtherTable, #id)` |

### Catatan Penting: Presisi Uang
Untuk kolom harga dan kuantitas yang memerlukan presisi:
- **Harga (Decimal 12,2)**: Simpan sebagai `integer` dalam satuan **sen** (x100). Contoh: Rp 15.500 = `1550000`.
- **Kuantitas (Decimal 12,3)**: Simpan sebagai `integer` dalam satuan **milliunit** (x1000). Contoh: 2.5 strip = `2500`.
- Alternatif: Gunakan `real` (double) jika presisi floating-point cukup untuk skala apotek.

## 4. Key Technical Decisions

### 4.1. Kenapa Drift, Bukan sqflite Mentah
- Type-safe query builder (compile-time error jika kolom salah).
- Reactive streams (`watch()`) — UI auto-update saat data berubah, tanpa manual refresh.
- Built-in migration system (versioned schema changes).
- JOIN, aggregate, subquery didukung langsung di Dart API.

### 4.2. Concurrency: SQLite vs PostgreSQL
PostgreSQL backend yang sekarang menggunakan `SELECT ... FOR UPDATE` (row-level lock) untuk mencegah race condition saat concurrent receipt/sale.

Di SQLite, **ini tidak diperlukan** karena:
- SQLite menggunakan **database-level write lock** (hanya 1 writer pada satu waktu).
- Drift `transaction()` sudah menjamin atomicity.
- Aplikasi desktop berjalan single-process, sehingga tidak ada concurrent HTTP request.

### 4.3. State Management: Riverpod
- `AsyncNotifierProvider` untuk data yang di-load dari DB.
- `StateProvider` untuk form state dan filter.
- `StreamProvider` + Drift `watch()` untuk live-updating tables.

### 4.4. Routing: GoRouter
- Auth redirect guard: Jika belum login, redirect ke `/login`.
- Setup redirect: Jika database kosong (belum ada pharmacy), redirect ke `/setup`.
- Shell route: Sidebar navigation persistent di semua halaman.

## 5. Data Flow (Contoh: Sale Transaction)

```
UI (SalesPage)
  │
  ├─ User scan barcode / search obat
  ├─ Tambah item ke cart (state: Riverpod)
  ├─ User klik "Bayar"
  │
  ▼
SaleService.createSale(pharmacyId, soldById, items, payment)
  │
  ├─ Validasi: invoice unique, items > 0, stock cukup
  ├─ database.transaction(() async {
  │     for each item:
  │       ├─ Query batch WHERE currentQuantity > 0
  │       │   AND expiryDate >= startOfToday
  │       │   ORDER BY expiryDate ASC (FEFO)
  │       ├─ Allocate across batches
  │       ├─ UPDATE batch SET currentQuantity -= allocated
  │       └─ INSERT sale_item_batch (allocation record)
  │     INSERT sale
  │     INSERT sale_items
  │     INSERT payment
  │     INSERT inventory_transactions (type: SALE, qty: negative)
  │   })
  │
  ▼
Provider invalidates → UI rebuilds with updated data
```

flutter build windows --release
